# F27 Joined phones draw every combo step as it was struck

Model: S · Written by the owner 2026-11-15 (found while building F26)
Status: ready

## What to build
On a joined phone, other captains' spear sweeps (combo step 2) show as pokes, because the combo step is not
sent from the host: the joined phone guesses step 1. Send the combo step with each strike (a small field in the
host's snapshot or strike event, backward compatible: an older host without it still works as before), and have
joined phones play the matching clip and F26 body turn for every captain, every step (poke, sweep, thrust; and
the sword combo's steps the same way). A move must look and do the same thing on every phone.

## Done when
`game/store/r_F27.mjs`: the host's captain strikes poke, sweep, thrust in order; the joined phone shows the
same clip for each step (clip name and F26 strike-face yaw match the host's within a frame). Same for a joined
phone's own captain seen on the host. r_F26 and r_F25 still pass; crown2sim and crown2online once at the end
(roles off and on).

## Design rules it relies on
Rulebook 9: animation decides how a move looks, code decides what it does and where it points.

## Where to start in the code
`graphify query "combo step strike snapshot"`. F26 added `render/rig/strikeface.js`; snapshots are built and
read in `net/netgame.js` (keep it under 800 lines: put new code in a small module if it grows).

## Out of scope
Hit rules, reach, timings (F25/F26 settled them).
