# C1 Champion framework

Model: O · Written 17 Nov from the design doc (rev 116, Champions section) and the code on `launch26` (d972bcb)
Status: built (not shipped), 17 Nov: C1a-C1g on launch26; C1h next

## What to build
A champion is one data file (under 300 lines): name, class, stats against the baselines, weapon, mount, 3-hit combo,
special attacks 1 and 2, champion ult, army ult, soldiers to recruit, influence on army. Numbers in config tables.
Shared level path 1-10 from match XP; special 1 at level 3, special 2 at 5, both ults at 7. Respawn stays on the
castle clock (CASTLE7). Health as shares of an infantryman; counter rule 120%. Every champion has a mount, used as
today (Ride). Champion chosen by setting or `?champ=` for now (lobby pick is S1-12).

## What the code has today (read 17 Nov)
- One captain for everyone (`mkUnit` in `core/sim/match.js`, `STATS.captain`): hp 150 (1.6 footmen, design 4x),
  a human hits 30 and a bot 22 (`HUMAN_CAPTAIN`); 3 weapons switched by a button (sword, spear, javelins).
- Captain power comes from the army's footman upgrades (`CAPTAIN_TIERS`, `applyFootTier`), not from levels.
  No XP or levels exist in a match (`XP` in config is the account rank after the battle).
- Shared captain moves: block/parry, evade, jump + leap slam, bash, heavy blow, rhythm and streak finishers,
  execution, duels, horse charge (`CHARGE`), shield-wall push, rally cry (`RALLY`). No ability slots or buttons.
- Recruits: one global list (`RECRUITS` = footman, archer). The footman is sword and shield, spear from upgrade 1.
  Army size: 5 + the side's castles shared out (`capOf`, `CROWN2.base/perCastle`). Aura upgrade still sold.
- Spear on a mounted man: x3 to the horse, and half of all other hits go to the horse (`hit()` in melee.js).
- Joined phones: the captain's state rides in `net/netgame.js` (788 lines, already over 500).

Every card: crown2sim and crown2online pass (no roles flag on launch26: one run each), r_PERF1c, lag no worse.

## C1g Base numbers (17 Nov, design doc rev 132: "Base champion, budget and guardrails", "Attack rate")
Arjun said "start work on C1g" 17 Nov. Read from the code on launch26 (b37ae41).
- Today: infantry 95 hp (`UNITS.inf`), champion hit .34 share; a page's stats are shares (`hp: 4, hit: .34, spd: 6.2`) and
  its horse a multiple (`mount.spd: 1` x `CAPTAIN_SPD.mount` 1.8). Swing timing is shared: a player's sword combo
  `CC.sword` .36/.36/.62 s (about 2.2 hits/s, finisher x1.5), the beat `RHYTHM.at` .52 s; a bot's blow every .6 s
  (`startSwing`, melee.js); reach 1.3 for everyone (`STATS.captain.reach` in army.js, match.js, netgame.js).
- Build: infantry 100. Pages in shown numbers: `stats: { hp: 400, dmg: 30, rate: 1.4, reach: 1.3, spd: 6.2 }`,
  `mount: { hp: 200, spd: 11.2 }` (m/s). Rate drives a bot's blow (1/rate) and a player's combo (cd, finisher cd, beat,
  spear timings all scaled so 3 hits take 3/rate s). Reach from the page. `CHAMP_BASE` and `CHAMP_LIMITS` in
  config/champs.js; `champions/limits.js` checks a page: every stat inside its floor and ceiling, budget 0 +-5%
  (health, damage per second, foot, horse; ranged reach +30%). Legionary takes the base numbers.
- The 42/s counts plain hits; the spin finisher (x1.5) stays the combo's reward on top, the same for every champion.
- Done when: `r_C1g` every page passes the limits; hits to kill follow 100/30; a bot champion's blows come 1/rate
  apart and a player's 3-hit combo takes 3/rate s (host and joined); crown2sim, crown2online, r_PERF1c pass; r_C1a-f
  updated to shown numbers.

## C1h Army shift (17 Nov, design doc "Army shift")
Replaces influence (`champions/influence.js`: one effect for the whole army, optional range). A page gets
`shift: { foot: { front, spd, dmg, hp, rate }, arch: {...} }` per soldier type, no range; limits: each within +-20%,
total 0 +-5% (checked by limits.js). Fire rate is new (archers' `shoot`). Done when: `r_C1h` a test champion's shift
lands on each kind and nowhere else, same on the joined phone; the limits refuse a shift over 20%.
