# F24 A frozen host doesn't split the battle

Model: O · Written 14 Nov (found in F22) from Arjun's "go"
Status: built (not shipped)

## What to build
- A joined phone takes over hosting after about 12 s of silence while the host's link is still open (a frozen,
  backgrounded or vanished phone), instead of 7.5 s; still 7.5 s when the link has closed. Numbers in
  `config.js` HANDOVER.
- A phone back from its own freeze doesn't count everyone else as gone or idle for the time it was frozen.
- An old host that comes back to find its players gone looks for the battle under the next code for 40 s and
  rejoins it as a player in its own army (the new host keeps that army for it). One battle, not two.
- A player marked idle still gives up his seat when he leaves (the old host could never notice them go).

## Done when
`game/store/r_F24.mjs` 9/9: host frozen 10 s: same battle, nobody loses anything; host frozen 40 s: another phone
hosts, the old host rejoins as a player, every phone has all three players and names. `store/handover.mjs` passes
(its wait is now 16 s).

## Trade-off
A host whose phone vanishes without closing its link now leaves everyone waiting about 12 s (was 7.5 s).

`game/src/net/netgame.js` (`clientTick`, `seekMovedBattle`, `handover`, `netHostReadInputs`), `game/src/net/p2p.js`.
